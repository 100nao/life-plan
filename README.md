# ライフプラン（個人用 PWA）

やりたい事・タスク・習い事・ジャーナルをまとめて整理する、自分専用のライフプランアプリです。
ビルド不要の静的ファイル（HTML / CSS / JS）だけで動き、外部ライブラリや CDN は使いません（例外は Googleカレンダー連携のための Google Identity Services のスクリプトのみ）。オフラインでも使えます。

- データはこのブラウザの **localStorage**（ジャーナルの写真は **IndexedDB**）に保存されます。コードやリポジトリにはデータは含まれません。
- 任意で **GitHub 同期**（プライベートリポジトリ `100nao/life-plan-data`）をオンにすると、AIコーチがデータを読み、アドバイスを返せます。
- 個人的な内容は最初から入っていません。サンプルが必要なときは「サンプルを追加」ボタンで入れます（まとめて削除もできます）。

## ファイル構成

| ファイル | 内容 |
|---|---|
| `index.html` | 画面の骨組み。iOS 用 meta、CSP（通信先は自分自身・`api.github.com`・`generativelanguage.googleapis.com`（Gemini）・`accounts.google.com` と `www.googleapis.com`（Googleカレンダー直接連携）） |
| `styles.css` | スタイル（ライト／ダーク、スマホ優先、PCではサイドバー） |
| `app.js` | アプリ本体（`.parts/p1〜p6.js` を連結したもの） |
| `sw.js` | Service Worker（全ファイルをキャッシュしてオフライン対応。GitHub API・Gemini API はキャッシュしない） |
| `manifest.webmanifest` | ホーム画面に追加するための設定 |
| `icons/` | アイコン（180 / 192 / 512 / maskable / favicon）。`tools/make_icons.py` で生成 |
| `images/` | 背景画像（かすみ・朝焼け・森・海）とキャラクター。`tools/make_images.py` で生成 |
| `tests/test_full.py` | Playwright による E2E テスト（GitHub API・Gemini API はモック） |
| `screens/` | テスト時のスクリーンショット |

`app.js` を直すときは `.parts/` を編集して `cat .parts/p[1-6].js > app.js` で作り直します（直接 `app.js` を編集しても動きます）。
アプリを更新したら `sw.js` の `CACHE_VERSION` を上げると、端末側のキャッシュが確実に入れ替わります。

## 主な機能

- **週間スタンプ**（v1.8.1 でホームと入れ替え、先頭タブ）：毎日の目標スタンプの一覧。旧ホーム画面は廃止（`#home` へのアクセスは週間スタンプに寄せます）
- **マトリクス**：緊急かつ重要／重要だが緊急でない／緊急だが重要でない／どちらでもない（上＝緊急、左＝重要）。iPhone は ⇄ をタップして移動、PC はドラッグでも移動
- **ステップ**：各項目に順番付きステップ（期限・完了チェック・並べ替え）、進捗バー、縦のステッパー表示。「💡 ステップのヒント」（引っ越し・資格取得・旅行計画・買い物 など）と「📋 番号付きリストから貼り付け」
- **ずっとできていない事**：作成日／最後の進捗からの日数。14日以上で「停滞」。理由タグ（時間がない／優先度が低い／気が重い／次の一歩が不明／お金／他人待ち／その他）と自由メモ
- **TASK**（v1.7.0 で旧「やりたい事」を改名）：分類（タスク／やりたい事／後回し／未整理）を問わず表示。期限（今日中／今週中／1ヶ月以内／1ヶ月以上、目標日で判定・v1.8.0 で分類フィルターから置き換え）・カテゴリ（プライベート／仕事の2択、v1.8.0〜）・重要度・時期（今年／1〜3年／5年以内／いつか＋日付）・状態の絞り込みと並べ替え。行ごとに折りたたみ、開くと詳細・操作が出る。初期表示は未完了のみ（v1.7.1〜）、行の左スワイプでも削除できる
- **後回しでいい事**：「やりたい事へ ↑」で昇格
- **習い事**：状態・頻度・月額・開始日・メモ・練習記録、今月の回数、継続中の月額合計
- **未整理**：とりあえずメモ → ワンタップで振り分け。「リマインダーから読み込み」。項目の確認は TASK の初期表示（未完了・期限すべて）から（v1.7.0 で専用タブは廃止し TASK に一元化）
- **ジャーナル**：日付・気分（1〜5）・関連タスク、検索。**📷 写真から追加**（手書きページを Gemini で書き起こし）、**📝 Obsidianから取り込む**（.md / .txt）
- **AIに相談（Gemini）**：アプリの中で Google Gemini と直接チャット。今のタスク・停滞・ジャーナルをふまえて答えます（下記）
- **コーチに相談**：GitHub 同期の予備として、状況のまとめ（テキスト＋JSON）をコピー／共有。返ってきたアドバイスやステップ JSON を貼り付けて取り込み
- **デザイン（v1.2）**：白〜オフホワイトの余白多めのデザイン。中央にキャラクター、左上の ☰ でメニュー（ドロワー、v1.3.1 から右側に出てスワイプでも開閉）。下には浮いた **すりガラスのタブバー**（週間スタンプ／マトリクス／TASK／カウントダウン／カレンダー、v1.8.1〜。〜v1.8.0 は先頭がホーム）があり、選んだタブへ「泡」がスライドします。後回し・習い事・AI・コーチ・完了履歴・設定・検索はメニューから（PC は左のサイドバーに全部）。項目・カテゴリ・象限ごとに絵文字アイコン。背景は **設定 → 表示** で「かすみ／朝焼け／森／海／なし」から選べます（画像はすべてアプリ内で生成した `images/` のもの。外部から読み込みません）。ライト／ダーク両対応、「視差効果を減らす」設定ではアニメーションを止めます

## GitHub 同期（AIコーチ連携）— 最初の1回だけ

1. GitHub で **Fine-grained personal access token** を作る
   （Settings → Developer settings → Personal access tokens → Fine-grained tokens → Generate new token）
   - Repository access：**Only select repositories** → `life-plan-data` だけ
   - Permissions → Repository permissions → **Contents：Read and write**（ほかは不要）
   - 有効期限は任意（切れたらアプリに「トークンが正しくないか、期限切れです」と出るので、作り直して貼り直す）
2. アプリの **設定 → GitHub 同期** でトークンを貼り付けて **「接続テスト」** を押す
   （owner `100nao` / repo `life-plan-data` / path `data/life-plan.json` / branch `main` は最初から入っています。変える場合は「詳細設定」）

以後は自動です。
- アプリを開いたとき・画面に戻ったとき・オンラインに戻ったとき・表示中は3分ごとに **自動で読み込み**（他の端末やコーチの変更をマージ）
- 変更すると約3秒後に **自動で保存**（内容が変わったときだけコミット）
- `data/coach-inbox.json` を **自動で取り込み**、「コーチに相談」画面にアドバイスとして表示（未読はドロワーのバッジで通知）
- 右上の雲アイコンが同期状態（緑＝同期済み／青＝同期中／赤＝エラー／黄＝オフライン）。手動の保存・読み込みボタンは設定の「手動操作・接続設定」にあります

マージは項目ごとに「新しく更新された方が勝つ」方式で、削除も記録（トゥームストーン、180日保持）して同期します。
トークンはこの端末の localStorage（`lifeplan.sync`）にだけ保存され、バックアップや GitHub のデータには含まれません。

## AIに相談（Gemini）— 無料の APIキーで

1. [Google AI Studio（aistudio.google.com/apikey）](https://aistudio.google.com/apikey) で **APIキーを作成**（Google アカウントでログイン → 「APIキーを作成」）
2. アプリの **設定 → AI連携（Gemini）** に貼り付け → **「接続テスト」**（成功するとキーが保存されます）
3. モデルは「最新のFlash（`gemini-flash-latest`、既定）」「`gemini-3.8-flash`」「`gemini-3.6-flash`」「`gemini-3.5-flash-lite`」から選べます。選んだモデルが使えない（404）ときは自動で次の候補に切り替わります

使い方
- メニューの「🤖 AIに相談（Gemini）」、または「コーチに相談」画面から開きます
- クイック質問：「今週何から手をつける？」「停滞タスクの原因を一緒に考えて」「このタスクをステップに分けて」「ジャーナルを振り返って」
- 「タスクとジャーナルを共有する」（既定オン）：未完了の項目（象限・状態・ステップ進捗）、停滞中の項目と理由、習い事、最近のジャーナル10件、今年のフォーカスの**要約**を一緒に送ります。オフにすると会話だけを送ります
- ステップ分解を頼むと、返事に「＋ ステップに追加」が出ます（同じ名前のタスク → 名前の一部が一致するタスク → なければ「未整理」に新規作成）
- 返事は「📓 ジャーナルに保存」できます。会話は「会話をクリア」で消せます

### ジャーナル：📷 写真から追加（手書き）
- ジャーナル画面の「📷 写真から追加」→ iPhone ではカメラで撮る／写真ライブラリから選ぶ（複数枚可、最大10枚）
- 端末内で長辺1600px・JPEG に縮小してから Gemini に送り、**手書きの文字をそのまま書き起こし**（読めない所は［判読不能］）。ページに書かれた日付も読み取ります
- 確認画面で写真のサムネイルを見ながら本文・日付・気分を直して「保存」。文中のタスクはチェックすると「未整理」に追加
- ページに緊急度×重要度のマトリクスが描かれていれば「▦ マトリクスに反映」で各象限に追加（同じ名前の項目があれば飛ばします）
- 写真そのものは、確認画面の「この写真もジャーナルに添付する」にチェックしたときだけ保存します（初期はオフ。保存先は下の「ジャーナルの写真」と同じ）。それ以外は文字だけ（`source: "photo"`）

### ジャーナルの写真（v1.3.1）— 保存先
- 写真はこの端末の **IndexedDB**（`lifeplan-photos`）に保存（1280px の本体＋360px のサムネイル）。`lifeplan.v1`（localStorage）や同期 JSON に入るのは **写真の id だけ**（`journal[].photos`）
- GitHub 同期をしているときは、**非公開**のデータリポジトリの `data/photos/<id>.jpg` に1枚ずつ保存し、他の端末は id を見て必要な写真だけ読み込みます。リポジトリが公開（`private: false`）だと分かったときは **GitHub には保存せず**、同期画面にエラーを出します（アプリ側の公開リポジトリには一切置きません）
- 削除は `deleted["photo:<id>"]` で他の端末にも伝わり、取り消せるよう2分たってから端末と GitHub から消します
- **JSON のバックアップには写真は入りません**（id だけ）。写真を残すには GitHub 同期を使ってください

### ジャーナル：📝 Obsidianから取り込む
- `.md` / `.txt` を1つ以上選ぶと、1ファイル＝1件のジャーナルに（`source: "obsidian"`）。本文の貼り付けも可
- 日付は ① フロントマターの `date:` ② ファイル名（`2026-11-01.md` など）③ ファイルの更新日 の順。フロントマターは取り除きます
- 同じ日付・同じ本文のものは重複として飛ばすので、同じフォルダを何度取り込んでも大丈夫です

### キーと会話の扱い

### ✨ 毎日の分析と 🤖 AI提案（v1.4.0）
- Gemini の APIキーがある端末で、**その日はじめて開いたときに1回だけ** Gemini が分析します（設定 → AIに相談 →「毎日の自動分析」、初期値オン）。同期が終わってから走り、同じ日の分析がすでに（別の端末で）できていれば呼びません。
- 送るのは **小さな要約だけ**（約4500字以内）：未完了タスク上位30件（象限・状態・停滞日数・ステップ）、直近7日の完了、習慣（直近14日の〇/×・連続日数）、習い事、直近14日のジャーナル本文（最大12件・各110字、写真は送らない）。キーは `x-goog-api-key` ヘッダーで **Google の API（generativelanguage.googleapis.com）にだけ** 送ります。
- 返事は JSON `{ "summary": "…", "insights": ["…"（最大3）], "taskSuggestions": [{ "title", "quadrant", "why", "steps": [] }]（最大3） }`。コードフェンス付きでも読みます。読めないときは本文を要約として表示し、提案は作りません。
- 毎日の分析の結果（要約・気づき）は記録として保持され、タスクの提案は「🤖 AI提案」画面に並びます（v1.8.0 まではホームの「✨ 今日の分析」カードでも表示）。「もう一度分析」は1日3回まで（AI提案画面の空状態や API から実行）。
- **「🤖 AI提案」画面**（☰ メニュー・PC のサイドバー・ホームのカードから）：Gemini とコーチの提案が日付ごとに並びます。理由とステップは開いて確認。象限を選び直してから「→ 自分のリストへ」で自分のタスク（`list: task`・選んだ象限・ステップつき・`source: "ai"`）になります。「×」で見送り。どちらも「元に戻す」可。「すべて移動」もあります。見送ったものは「これまでの提案」から戻せます。
- 提案は **自分のタスクとは別のリスト**（`aiSuggestions`）に入り、勝手にタスクにはなりません。設定「AI提案を自動で自分のリストに移す」（**初期値オフ**）をオンにすると、届いた提案（Gemini・コーチ両方）をすぐ自分のリストへ移し、「元に戻す」で AI提案に戻せます。
- 既存の未完了タスク・未処理の提案と同じ（またはほぼ同じ）タイトルの提案は作りません。
- 端末ごとの設定（`lifeplan.ai` の `daily` / `autoMove`）と、その日の実行記録（`lifeplan.aiDaily`）は同期しません。分析結果（`aiAnalyses`、1日1件・最新30日）と提案（`aiSuggestions`）は同期します。

### 📅 Googleカレンダー連携（v1.6.0）— アプリが直接読み書きする

アプリ自身が Google Identity Services でオーナーの Google アカウントの許可をもらい、**Google Calendar API を直接**読み書きします。中継ファイル（`data/calendar.json` / `data/calendar-links.json`）も、毎朝のコーチも使いません。

**最初の1回だけ（端末ごと）**
1. [Google Cloud Console](https://console.cloud.google.com/apis/credentials) でプロジェクトを作り、**Google Calendar API を有効化**する。
2. **OAuth クライアントID（ウェブアプリケーション）**を作成し、「承認済みの JavaScript 生成元」にこのアプリのオリジン（例：`https://100nao.github.io`）を登録する。OAuth 同意画面では自分のアカウントをテストユーザーに加える（個人用なら「テスト」状態のままで自分だけ使えます）。
3. アプリの **設定 → 📅 Googleカレンダー連携** にクライアントIDを貼って保存 →「Googleと連携する」を押して許可する。

**読み取り（Google → アプリ）**
- 取得タイミング：連携したとき・アプリを開いたとき・画面に戻ったとき・表示中は30秒ごと。
- 範囲（v1.7.0〜）：選択中（selected）の**全カレンダー**の、過去30日〜未来180日の予定 ＋ メインカレンダーのタイトルに「⏳」を含む2年先までの予定。（v1.6.0 ではメインカレンダーの今日から約90日間 ＋「⏳」2年でした）
- アプリでの表示：ホーム「📅 これからの予定」（今日から7日間・最大6件）、カウントダウン画面の「📅 Googleカレンダーの予定」一覧（各予定に「→ カウントダウンにする」）、「Googleカレンダー最終取得: <取得時刻>」。
- タイトルに **「⏳」を含む予定** は、自動でカウントダウンとして並びます（Google バッジ・読み取り専用・アプリには保存しない）。ただし、アプリのカウントダウンとつながっている予定（カウントダウンの `gcalId`）は重ねて出しません。
- 「→ カウントダウンにする」で、`source: "google"`・`gcalId: "<event id>"` のカウントダウンを作ります（同じ予定から2つは作りません）。`source: "google"` のカウントダウンは、ここで変えても Google 側は変わりません。

**書き込み（アプリ → Google、その瞬間に実行）**
- カウントダウンの「📅 Googleカレンダーにも入れる」がオンで保存すると、その場で **終日予定「⏳ <title>」**（日付 = `date`、説明 = `memo`）を作成し、返ってきた event id を `countdowns[].gcalId` に保存します。
- 編集して保存すると、その場で Google の予定を更新します（Google側で消えていたら作り直します）。
- カウントダウンを削除、または「Googleカレンダーにも入れる」をオフにすると、その場で Google の予定を削除します。通信に失敗したときだけ `gcalDeletes[]` に依頼を残し、次回の取得時に自動で再試行します（v1.5.0 で溜まった依頼も、連携すれば自動で処理されます）。

**キーとトークンの扱い**
- クライアントIDとアクセストークンは **この端末の localStorage（`lifeplan.gcal`）だけ** に保存。GitHub 同期・バックアップ（JSON 書き出し）には含まれません。
- アクセストークンの有効期限（約1時間）が切れたら、設定で「Googleと連携する」を押し直してください（自動で取り直せる場合は押し直し不要です）。
- 連携は端末ごとです。使う端末ごとにクライアントIDの保存と許可が必要です（クライアントIDは同じもので大丈夫です）。
- スコープは `https://www.googleapis.com/auth/calendar.events`（予定の読み書き）と、v1.7.0 から `https://www.googleapis.com/auth/calendar.calendarlist.readonly`（カレンダー一覧の読み取りのみ）。v1.6.0 から使っている場合は、カレンダータブのために「Googleと連携する」の押し直しで許可が追加されます。
- CSP は `accounts.google.com`（連携ライブラリと許可画面）と `www.googleapis.com`（Calendar API）への通信を許可します。Service Worker は外部ドメインをキャッシュしません。

**アプリが書くフィールド（`data/life-plan.json` の `data`）**
- `countdowns[].gcal`：`true` なら「📅 Googleカレンダーにも入れる」がオン。
- `countdowns[].gcalId`：つながっている Google の event id（直接連携ではアプリ自身が書き込む）。
- `gcalDeletes[]`：直接削除に失敗したときだけ残る再試行用の依頼。通常は空です。

> v1.5.0 の中継ファイル方式は、クライアントID未設定のときのフォールバックとしてだけ残っています（`data/calendar.json` / `data/calendar-links.json` があれば読みます）。直接連携が有効な場合は使いません。

### v1.8.1 — スワイプで画面がずれる不具合の修正／週・日をタイムグリッド化／マトリクスの切り替えをカテゴリに／カウントダウンのドットグリッド／ホームを廃止し週間スタンプを先頭タブに

- **不具合の原因と修正（スワイプで画面全体が左にずれて戻らない）**：月グリッドの列指定 `repeat(7, 1fr)` は `minmax(auto, 1fr)` と等価で、列の最小幅は中身の min-content で決まります。iOS Safari では、日セル内の `white-space: nowrap` な予定チップ（長い会議名など）の min-content が列幅を押し広げ、グリッドが画面の約2倍幅まで膨張していました。その結果、文書全体が横スクロール可能になり、横スワイプでブラウザが文書をパンして、その位置のまま固まっていました（ドロワーのドラッグ追随は `.gtab-view` 内のタッチを最初から受け付けないため無関係です）。修正：列を `repeat(7, minmax(0, 1fr))` にし、セル・チップに `min-width: 0` 等を与えてチップがセル内で省略されるようにしました。あわせてジェスチャの所有権を明確化しました：`.gtab-view` に `touch-action: pan-y`（横方向はブラウザに渡さない）、横スワイプ確定時は `touchmove` を `preventDefault`、`html/body` に `overscroll-behavior-x: none`。
- **週・日表示をタイムグリッドに**：週表示を日ごとのリストから、Google カレンダーの週表示と同じ時間軸グリッドに作り替えました（曜日・日付ヘッダー〈今日は丸くハイライト〉＋終日の帯＋0:00–24:00×7列）。日表示も同じ描画の1列版です。時間指定の予定は開始〜終了に応じた位置・長さのブロックで表示し、重なる予定は横並びになります。グリッド内は縦スクロールでき、初期位置は8時付近（今日を含む表示では現在時刻付近）です。ブロックのタップで従来の詳細シートが開きます。
- **ダブルタップで日表示へ**：月表示のセル、または週グリッドの列（予定のない場所）をダブルタップすると、その日の日タイムラインに切り替わります。シングルタップは従来通り選択のみで、遅延は入れていません（2回目のタップで遷移）。
- **マトリクスの切り替えをカテゴリに**：上部のチップを種別（すべて／タスク／やりたい事／後回し／未整理）から、カテゴリ（すべて／仕事／プライベート）に置き換えました。象限内のアイテム・件数バッジ・未分類トレイが選択中カテゴリで絞り込まれます。カード上の種別表示や TASK 画面のフィルターには影響しません。
- **カウントダウンのカードにドットグリッド**：従来の進み具合バーを、参考デザインのドットグリッドに置き換えました。1マス＝1日で、スパン＝作成日→対象日。経過（作成日〜今日）＝グレー、残り（明日〜前日）＝水色、対象日＝オレンジ。総日数が210を超える場合は1マス＝1週間に切り替えてマス数を抑えます（「あとN日」の数字は日数のまま）。作成日が無い・対象日より後などの不整合データでは「残りのみ」等に倒して壊れません。当日は対象日マスのみ、過ぎたものは全グレー＋対象日マスで表示します。対象はカウントダウンタブのカードのみ（旧ホームの mini 表示は下記のホーム廃止で終了）。
- **ホームを廃止し、先頭タブを「週間スタンプ」に**：下部タブは左から 週間スタンプ／マトリクス／TASK／カウントダウン／カレンダー。週間スタンプは従来の習慣スタンプ画面（ドロワーの「🐣 習慣スタンプ」と同じ画面）です。起動時の既定ルートも週間スタンプになり、`#home` や不明なルートは週間スタンプに寄せます（保存済みの状態が残っていても壊れません）。PC サイドバーとドロワーのホーム導線も週間スタンプに付け替えました（ドロワーの「習慣スタンプ」リンクは併存）。ホーム専用だった表示（ヒーロー、コーチ新着カード、今日の分析カード、カウントダウン mini、これからの予定、停滞リスト、今年のフォーカス等）は廃止です。各機能自体は残ります：コーチのアドバイスは「コーチに相談」画面、毎日の分析は起動時に自動実行され提案は「🤖 AI提案」画面、予定はカレンダータブ、カウントダウンはカウントダウンタブで見られます。

### `data/coach-inbox.json`（AIコーチが書く・アプリが自動で取り込む）

```json
{
  "messages": [
    {
      "id": "2026-11-01-weekly",
      "date": "2026-11-01",
      "title": "今週のフォーカス",
      "text": "緊急かつ重要のうち「9hoursパリティ解消」を最優先に。英会話は停滞中なので、まず無料体験の予約だけでOK。",
      "stepSuggestions": [
        { "taskTitle": "英会話", "steps": ["オンライン英会話を3社比較", "無料体験を予約"] }
      ],
      "taskSuggestions": [
        { "title": "区役所の受付時間を調べる", "quadrant": "q1", "why": "パスポート申請の前に必要なため", "steps": ["区のサイトを見る", "カレンダーに入れる"] }
      ]
    }
  ]
}
```
- `id` ごとに1回だけ取り込みます（同じ `id` を書き直しても重複しません）。新しいメッセージは配列に **追記** してください。古いものは消しても構いません。
- `text`（または `advice` / `message` / `body`）が本文。`title`・`date`・`stepSuggestions` は任意。
- `stepSuggestions[].taskTitle` はタイトルの完全一致 → 部分一致で項目を探し、見つからなければ未整理に新しい項目を作ってステップを追加します（同じ文のステップは重複しません）。
- `taskSuggestions`（v1.4.0〜・任意）は **新しいタスクの提案**。形式は厳密に `[{ "title": "…", "quadrant": "q1|q2|q3|q4", "why": "…", "steps": ["…"] }]`：
  - `title`（必須・文字列）／`quadrant`（`q1` 緊急かつ重要・`q2` 重要だが緊急でない・`q3` 緊急だが重要でない・`q4` どちらでもない。ほかの値は `q2` 扱い）／`why`（任意・理由）／`steps`（任意・文字列の配列、最大10）。
  - 自分のタスクには **直接入らず**、「🤖 AI提案」画面に `source: "coach"` で並びます（id は `sug:coach:<メッセージid>:<配列の位置>`）。ユーザーが「→ 自分のリストへ」を押すか、設定「AI提案を自動で自分のリストに移す」がオンのときだけタスクになります。
  - 既存の未完了タスクや未処理の提案と同じタイトルのものは作りません。既存タスクにステップを足したいときは `stepSuggestions` を使ってください。
  - `text` がなく `taskSuggestions` だけのメッセージも受け付けます（「タスクの提案」として表示）。
- 配列だけ（`[ {...}, {...} ]`）や、1件だけのオブジェクトでも受け付けます。

## 公開（ホスティング）について

- iPhone の「ホーム画面に追加」とオフライン動作には **HTTPS** が必要です（`localhost` は例外）。
  例：GitHub Pages、Cloudflare Pages、Netlify などの静的ホスティング。
- **アプリのコードを置くリポジトリと、データの `life-plan-data` リポジトリは分けてください。**
  データ用はプライベートのまま、アプリ側にはデータを一切置きません（アプリにはデータは含まれていません）。
- GitHub Pages で公開すると URL を知っている人は画面を開けますが、データは各自のブラウザにしか無く、トークンが無ければ GitHub のデータも読めません。
- iPhone：Safari で開く → 共有 → 「ホーム画面に追加」。

## 制限・注意

- iOS Safari は、ホーム画面に追加していないサイトのデータを長期間使わないと消すことがあります。ホーム画面に追加して使い、GitHub 同期か定期的な JSON 書き出しを推奨します。
- トークンは端末の localStorage に平文で保存されます。対象を `life-plan-data` だけ・Contents 権限だけにしたトークンを使ってください。端末を手放す前に「接続を解除」。
- 自動保存は変更ごと（約3秒まとめて）に GitHub へ1コミットします。コミット数は多めになります。
- 同時に2台で同じ項目を編集した場合は、後から更新した方が残ります（項目単位）。
- 実際の GitHub への接続はテストしていません（テストはモックの GitHub API で実施）。
- 通知（プッシュ通知）はありません。
- Gemini 連携はモックの API でテストしています（実際の Google への接続・手書き認識の精度は未検証）。
